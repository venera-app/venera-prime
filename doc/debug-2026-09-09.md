## Credential migration policy update

This section supersedes the credential-exclusion policy recorded below, at the user's explicit request.

- Manual exports now include full appdata, source account/password/token data and cookie.db. Sync exports include source credentials and cookies while retaining existing device-local and user-configured settings exclusions.
- Manual import restores WebDAV configuration when present. Automatic WebDAV import keeps the active device's endpoint/credentials to avoid redirecting future synchronization.
- Cookie snapshots use SQLite VACUUM INTO for consistency. Import validates cookie database integrity/schema before replacing data, includes it in tracked rollback and reopens the same cookie jar object so existing interceptors see restored sessions.
- Backups without cookie.db preserve the device's existing cookies. Earlier redacted backups cannot recover credentials they never contained. Expired or server-revoked sessions may still require login.
- Source JSON is validated without deleting credentials. Log URL/header redaction remains enabled; malformed source JSON errors do not print credential-bearing parser snippets.
- English, Simplified Chinese and Traditional Chinese settings notices explain that backups contain credentials, imports must be trusted, and WebDAV should use a trusted HTTPS server. Backup encryption is not implemented.
- Manual export and WebDAV success/failure paths clean temporary credential-bearing archives. Download staging uses a generated directory instead of trusting a server-provided filename as a local path.
- Native-ZIP regression suite: 65 passed, one optional network probe skipped. Coverage includes credential/source/cookie export-import round trips, settings exclusions, manual WebDAV restoration, automatic endpoint preservation, missing-cookie compatibility and rejection of a corrupt cookie database without losing current data. Network logging redaction test passed.
- Final Flutter analyze and 65-test regression run passed; Android/Linux debug builds passed including the temporary-file cleanup adjustment. The Android APK was installed with ADB while preserving data. No real WebDAV account or production backup was used in these tests.

## Changes

- Removed the legacy catalog widget and its duplicate configuration editor.
- Kept one-way migration of the old catalog URL; deleting a migrated catalog no longer recreates it.
- Source switches pass their candidate URL directly into the locked update operation. Failed switches do not modify the shared candidate URL; successful updates retain their actual download URL.
- Catalog configuration changes and new update checks invalidate cached update candidates.
- An unavailable, disabled, or missing offering from an existing origin does not silently select another catalog.
- HTTP/HTTPS validation rejects other schemes and embedded URL credentials. Duplicate catalog URLs are rejected during editing. Malformed optional numeric/list fields tolerate old or damaged settings.
