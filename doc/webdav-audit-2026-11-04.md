# WebDAV 全功能同步检查（2026-11-04）

检查基线：2.7.1，HEAD `05197d8`。对照 2.6.1、2.6.2、2.6.3、2.7.0 的相关改动；主线程检查传输、备份与调用链，Luna 并行复核数据类别。以下审计描述修复前状态；用户随后授权修复，处理结果见文末。未访问用户 WebDAV 服务，未变更版本或发布内容。

## 结论

存在部分功能变更不会自动上传的问题，也存在连接建立后同步长期卡住、旧版快照丢失新版搜索信息的风险。现有测试通过不能排除这些问题；它们主要覆盖显式调用上传/下载，而非所有功能操作是否触发同步。

### 1. 自动上传触发遗漏（优先修复）

`lib/utils/data_sync.dart:94` 只订阅本地收藏与漫画源管理器，未订阅历史、图片收藏、稍后阅读和阅读统计管理器。

- 稍后阅读：添加、移除、批量删除、撤销恢复、清空均只通知自身监听者（`lib/foundation/read_later.dart:228` 起）；详情页和菜单调用方也没有补发上传。
- 历史记录：删除、清空、清除未收藏记录只通知历史管理器（`lib/foundation/history.dart:362` 起）。
- 阅读统计：删除单本、清空只通知统计管理器（`lib/foundation/reading_statistics.dart:223` 起）。
- 图片收藏：图片收藏页删除操作只通知图片收藏管理器（`lib/foundation/image_favorites.dart:351`）；不会触发 WebDAV 上传。

以上数据都在备份范围内，手动上传或随后修改设置、收藏等触发整包上传时会带上它们。因此表现往往是“有些功能能同步、有些一直没更新”。阅读器退出会额外调用 `DataSync.onDataChanged`（`lib/pages/reader/reader.dart:526`），所以正常退出阅读器时的阅读进度、统计及阅读器内图片收藏变更通常会被带上，不能概括为整个历史或图片收藏功能完全无法同步。

临时诊断测试开启自动同步，依次清空稍后阅读、历史与统计后，观察到 DataSync 通知数为 0、无上传、无排队。图片收藏缺口通过管理器及两个删除入口调用链确认。

建议修复时区分实际内容变化、初始化通知和高频阅读进度，保留恢复过程防回传与自动同步开关；不宜简单把所有 UI 通知都变成上传。

### 2. 连接后等待响应缺少有效超时（优先修复）

`lib/network/app_dio.dart:374` 原生客户端仅配置连接超时及 keepalive，未设置总请求超时；`:423` 起的 `RHttpAdapter.fetch` 未将 Dio 的接收/发送超时和取消信号映射到原生请求。WebDAV 使用这个适配器。

临时本地 HTTP 测试把 Dio `receiveTimeout` 设为 100ms，服务端收到请求后保持 400ms 不发响应头，客户端仍未结束或报超时；随后释放响应则正常得到 200。该测试确认的是响应头等待阶段，不是所有接收阶段都没有超时。

若服务器或代理接受连接后长期不回复，同步的 `isUploading` / `isDownloading` 会持续占用，后续任务循环等待。keepalive 不是业务请求完成期限。尚未证明这是用户实际服务器的问题；该风险在最近几版仍存在，网络适配器最近一次修改早于 2.6.x。

### 3. 混用旧版本会清空新版搜索详情

2.7.0 新增 `searchRecords`，保存来源、筛选、页码等。`lib/foundation/appdata.dart:367` 无条件恢复该字段；旧备份缺字段时，`SearchHistoryEntry.decode(null)` 返回空列表。2.6.x 设备也不会保存和回传这个新顶层字段。

因此新设备下载旧设备上传的快照后，搜索词可能还在，但详细搜索记录和页码消失。临时测试以已有第 8 页搜索记录导入缺少 `searchRecords` 的数据，确认列表被清空。所有设备升级可避免旧客户端再次丢弃该字段；兼容策略应明确“缺少字段”与“明确清空”的区别。

### 4. 日期优先排序会让时钟偏差压过新版本

`lib/utils/data_sync.dart:30` 先比较文件名日期，再比较递增版本号。临时测试确认 `20001-10.venera` 排在 `20000-11.venera` 后面（即被认为更新）。

若设备 A 时间偏快一天，设备 B 虽然扫描远端后上传了版本更高的新快照，但日期较小，下载仍优先选 A 的旧快照。`:429` 的已同步标记还可能将此次下载直接判为“没有新数据”。这不是普通日期一致场景下必现的问题；恢复设备时间正常也不会立即消除远端未来日期快照的影响。建议重新设计以递增版本为主、兼容旧命名的选择策略，并覆盖时钟回拨用例。

## 全部主要数据类别覆盖

| 类别 | 是否进入同步备份 | 检查结果 |
| --- | --- | --- |
| 本地收藏、收藏夹、追更数据 | `local_favorite.db` | 管理器监听可触发上传；2.7.0 追更检查期间合并自动上传，最后一批完成才发送，手动上传可绕过批处理 |
| 阅读历史、章节与页码 | `history.db` | 退出阅读器触发上传；单独删除/清空有触发遗漏 |
| 图片收藏 | `history.db` 内的表 | 阅读器退出可带上变更；图片收藏页单独删除有遗漏；图片缓存本身不打包 |
| 稍后阅读 | `read_later.db` | 内容纳入备份，独立增删缺自动触发 |
| 阅读统计 | `reading_statistics.db` | 退出阅读器可带上变更；独立删除/清空缺自动触发 |
| 搜索词、来源、筛选、页码 | `appdata.json` 顶层 | 新版支持；翻页先本地保存、离开搜索再上传；旧版本往返会丢新字段 |
| 首页顺序、隐藏模块、紧凑布局、收藏夹入口 | settings 的 `homeLayout` | 保存时调用 `saveData()`；隐藏同步卡片仍保留生命周期监听 |
| 瀑布流、双页、手动跨页配对及其他普通阅读设置 | settings | 纳入同步；跨页配对存于 `readerSpreadOverrides`，保存触发上传；受用户排除字段限制 |
| 漫画源脚本、源数据、账号 | `comic_source`、settings | 纳入备份；源变更监听触发上传；坏 JSON/数据库校验失败会中止整包，需看错误日志 |
| Cookie | `cookie.db` | 使用 SQLite 快照导出并恢复 |
| WebDAV 地址/账号、自动开关、上次同步标记 | 设备配置 | 自动同步不覆盖另一端的配置；自动开关与标记在 implicitData 中，各设备独立 |
| 代理、解锁、统计记录开关、阅读方向记忆等 | 明确排除字段或 implicitData | 设备独立，不应当作上传失败；用户自定义排除字段同样不覆盖 |
| 本地漫画文件、下载任务、离线库分类/排序 | 本机文件与 `local.db` 等 | 不在现有 WebDAV 快照范围，2.7.0 本地分类也不会跨设备同步；属于当前范围限制，不是服务器传输错误 |

同步仍是整包快照覆盖，不会自动合并不同设备同时产生的修改。启动及首页恢复前台超过 10 分钟会检查下载，没有持续远端推送；短时间来回切换设备不能保证立即自动拉取。

## 用户授权后的修复

- 稍后阅读增删、撤销、批量删除及清空，历史删除/清空，统计删除/清空，图片收藏增删现在主动通知既有 DataSync 实例。数据库初始化不发送同步事件；阅读进度仍在阅读器退出时集中上传。自动同步开关与恢复防回传检查继续生效。
- 备份选择与按数量清理改为递增版本优先，再比较日期和唯一后缀；新增未来日期旧备份与回拨日期新备份并存的真实下载测试。
- 老快照缺少 `searchRecords` 时保留本机详细搜索记录；明确携带空列表时仍执行清空。
- WebDAV 显式设置连接超时 15 秒、发送与接收超时 60 秒。网络适配器接入每个请求独立的原生取消令牌，覆盖等待响应头和数据流停顿；共享连接池不因单请求取消而整体关闭。

新增测试通过本地 HTTP WebDAV 服务逐项执行 13 种功能操作，验证启用自动同步时实际 PUT、关闭时不上传；既有恢复测试继续确认下载不回传。最终 14 个测试文件共 41 项测试全部通过，包含上面的 13 种操作及新增网络响应头/响应体超时、发送停滞、主动取消、拒绝连接、提前响应、慢上传与后续请求验证。修改范围 11 个 Dart 文件静态分析无问题，`git diff --check` 通过。

最终测试日志：`/tmp/venera-webdav-final-tests.log`；静态分析日志：`/tmp/venera-webdav-final-analyze.log`。本次未提交、推送、升版或发布；尚未验证用户实际 WebDAV 服务及真机后台行为。

这些修改不改变整包快照覆盖策略；操作系统挂起或直接终止进程时，仍不能保证后台网络传输完成。本地下载文件与离线分类仍不纳入 WebDAV 同步。
