## 本轮补充反馈

### Windows WebDAV

Windows 系统代理读取未初始化 WinHTTP 输出结构，也未检查 API 返回值；失败时可能使用无效指针，且数组使用了错误的 `delete`。现已初始化、检查失败、使用 UTF-8 与 `delete[]`。后续复核又修正仅含 `http=host:port` 的单项系统代理被误判为无效的问题，并测试协议列表、空白、HTTPS 优先与有效 HTTP 回退。WebDAV 的传输回归使用本地 HTTP 服务，不能等同验证用户的坚果云/NAS、系统代理、证书和账户。仅凭“PC 无法同步、安卓可以”仍不足以定位用户故障的唯一原因；需要 Windows 的错误提示或日志继续核对。

### 存储路径迁移

原逻辑先持久化新路径，再删除旧目录，最后才更新内存路径。Windows 文件占用导致删除失败时，新旧状态不一致，甚至继续读取已经部分删除的旧目录。现在完整复制并持久化后立即切换新目录；旧目录清理失败只记录日志并保留旧文件。复制改为 64 KiB 分块，避免将大文件整份载入内存，并在隔离线程使用同步 SAF 接口。

选择器错误现在显示给用户；设置页明确说明须选择空文件夹，并完成或取消排队下载。这两个限制继续保留，避免覆盖已有文件或让下载写入迁移中的目录。部分复制失败后的目标目录可能仍留有已复制文件，此时应选择新的空目录；不会删除源数据。

### 检查更新时持续上传 WebDAV

收藏检查本身已批量通知，但漫画源请求仍可能不断保存变化的 token/源数据。新增可嵌套、可重叠的自动上传批处理：检查期间只标记有变更，最后一批结束后上传一次，异常/取消通过 finally 释放。手动上传可即时执行；关闭自动同步仍会阻止最终上传。已有上传不被中断；排队自动请求执行时也会重新经过批处理与开关检查。

### 安卓下载完成后停住、继续时闪退

确认并修正了相关链路中的缺陷，但尚未取得原漫画/章节/源脚本和闪退栈：

- 同一下载的异步运行串行化，快速暂停/继续不会让旧运行与新运行同时修改游标；旧章节/旧任务的完成回调不再启动新章节的调度。
- 完成入库和队列持久化可等待；入库失败保留可重试任务，记录错误，不先从队列丢弃。
- SAF 原生调用长期附着于 Dart 线程，原来未释放 JNI 局部引用；新增每次调用的局部引用帧。句柄引用计数读写加锁，避免读写线程和 finalizer 竞争。
- SAF 整文件读取原来依赖 fstat 大小和单次 read；改为读至 EOF，处理管道、短读和 EINTR；写入处理短写。读取失败显式报告异常，不伪装成空图片。工作 isolate 的错误回传不再被吞成 null。
- 为让修复随应用构建生效，将原固定提交的 flutter_saf 源码内置到 `packages/flutter_saf`，保留 LICENSE 和 UPSTREAM.md；没有直接修改共享 pub 缓存。

## 其它回归中发现的问题

- 连续阅读从上一章末尾返回后，残留的末尾定位会覆盖显式跳页；用户跳页现在终止末尾自动定位。
- 刷新/离开图片时的正常取消不再被图片解码器上报为全局加载异常；真实网络/解码错误继续显示。
